# 局部时间控制与独立细轨迹复核结果

**本轮得到一个通过原门槛的 3–3.5 ms 受载塑性响应诊断区间；没有完成沉积，也没有新增正式过程接受时间。**
这是独立 450 C 热态、918 粒子、20 ms 速度启动的 QS 工程近似模型。
20 ms 是速度启动时长，实际仅计算到 3.5 ms，不能说已完成启动或已达到 300 rpm。

运行前范围和停止条件在 `LOCAL_TIME_CONTROL_CONTRACT_20261005.md`。旧 ramp 第四块的
3.5 ms FAIL 原样保留，新研究没有追认旧候选，也没有修改材料、接触、热学或容限。

## 修改及依据

原诊断比较从共同零时刻出发的两条完整轨迹，进入接触后应力与塑性历史出现显著差异。
力平衡和能量门通过不能替代时间准确度。法向接触离散功一致性也不能保证接触启始
时刻的载荷历史足够准确；现有证据不足以认定唯一根因。

新增 `scripts/bounded_time_control.py` 和 `scripts/run_local_time_control.py`：

- 每组整步与两半步从完全相同的直接父状态出发；各候选独立加载完整 checkpoint。
- 时间比较失败时保留原父状态，最多减小到预登记的最小步；保留所有失败和成本。
- 每个候选仍调用冻结的 `ramped_hot_candidate.candidate`，包括真实三维邻域、材料、
  多面接触、热反馈、fresh 残差、原始与全前缀能量、几何路径及标量等价检查。
- 主线局部通过后，必须从同一个 3 ms 起点另跑独立连续细轨迹，复核每个主线半步终点。
- 新 `scripts/readback_local_time_control.py` 仅读保存数据，独立重算比较和控制器决策，
  核对全部 918 ID、全特征接触记录、直接父链、预算、来源及监督日志。

控制器 9 项纯逻辑检查通过，收据 `outputs/bounded_time_control_20261005/v2/receipt.json`。
它们不是 9 个 AFSD 验证。首版检查中浮点终点断言过严的失败保留在 v1；物理运行前已修正。
新驱动接线另经静态复核、实际旧 checkpoint 的保存数据比较，以及真实预检。
未重新运行历史整包回归。

## 重跑与下一实际关口

使用项目 `.envs/pysph/python.exe -B`，三个线程环境变量 `OMP_NUM_THREADS`、
`OPENBLAS_NUM_THREADS`、`MKL_NUM_THREADS` 均为 1。在全新输出目录调用：

```text
scripts/run_local_time_control.py --output <new-output> --phase primary --index 1
scripts/readback_local_time_control.py --base <new-output> --phase primary --index 1
```

后续每阶段先检查读回和 controller 状态，再递增 index；仅
`PRIMARY_COMPLETE_INDEPENDENT_REPLAY_REQUIRED` 允许开始 `--phase replay --index 1`。
本次实际主线 index 1–10、复核 index 1–8；该列表是运行记录，不是忽略失败的盲目循环。
各阶段 `supervision.json` 与读回摘要保存了实际命令、退出码和完整 SHA256 证据图。

下一关口是以单独登记的正式启动协议验证共同零时刻的完整历史，并测试下一受载窗口
与更大有效步长的成本；不能直接把本次诊断 checkpoint 改成 accepted 后续跑。
之后仍需真正的孔口输运、肩下铺展及连续送料验证。原 FKS、Jaumann 大变形闭循环能量、
空间分辨率和实验验证问题仍未解决。本轮不能据此承诺完整沉积的完成日期。
